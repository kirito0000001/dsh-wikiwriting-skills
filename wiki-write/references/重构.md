# 重构：从「素材堆」到「一篇文章」

> **本文归属的规则**：`WRC-nn` ｜ 来源与许可见 §8
> 素材是**按问题**堆起来的（`Q1…Q7`）。本文件负责把它变成**按读者**排的一篇文章。

---

## 0. 什么时候需要重构

**三种情况必须先重构再落笔**：

1. 素材来自**多处**（多个仓库／多部作品／多轮对话）；
2. 素材**按采集顺序**堆着（问题分组 ≠ 阅读顺序）；
3. 你自己都说不清"这篇最重要的一句话是什么"。

**唯一不需要重构的情况**：素材本来就只有一个问题、一个来源、一条线。那就直接写。

---

## 1. 定读者与主线（先做这一步，别跳过）

| 要回答 | 怎么算答出来了 |
| --- | --- |
| **读者是谁** | 具体到**他正在干什么**（不是"开发者"，而是"想把 X 接进自己项目的 UE 程序员"） |
| **他要拿这篇干什么** | 决定什么算重点。答不出 → 回选题卡 |
| **这篇只承诺哪一件事** | **一句话**。写不出来说明它其实是两篇（见 §5） |
| **他读完该能做什么／记住什么** | 一个动作，或一个判断 |

> **主线不唯一就别往下写。** 一篇里塞两个互不支撑的"所以呢"，读者一个都记不住。

**产出**：一句 `本文承诺：让 <读者> 能 <动作/判断>。` 写在草稿最上面，写完删掉。

---

## 2. 去耦合：把「因为 X 所以 Y」拆开查

采集阶段按问题分组，会让**跨问题的因果**看起来理所当然。落笔前逐条过：

- 这条因果**在素材里有证据**吗？还是"读起来顺"就写上了？
- 两个事实并排写，**读者会不会读出一个我没说的结论**？
  > 这是最隐蔽的一种错误：**把 A 和 B 放在一起，暗示一个两者都没说的 C。**
  > 素材里 A 和 B 各自为真，不代表 A→B 成立。
- 这条**是"文档这么说"还是"事实如此"**？（账本的 `状态` 字段就是为这个设的）

**动作**：把可疑的因果**降级为并列陈述**，或补一条证据。补不上就删掉那半句。

---

## 3. 按读者重排（「重点错误」几乎全出在这一步）

**默认顺序是错的**：你按**工作顺序**（先试了什么、后来发现什么）写，读者要的是**结论先行**。

**重排三条**：

1. **最重要的放最前** —— 首屏（标题 + 开头两段）要能让读者判断"这跟我要做的事有没有关系"。
2. **背景不能省，但可以后置** —— 读者不知道"为什么需要这个"，前面所有细节都白写；但它不必是第一段，可以在"先给结论"之后紧接着补。
3. **术语首现即解释** —— 不是加术语表（那是治症状），是**第一次出现时就地解释**。

**自查一句**：把每一节的**第一句**单独抽出来读一遍 —— 它们能不能连成一条线？连不成，说明顺序是"采集顺序"而不是"阅读顺序"。

---

## 4. 删与补

**删**（草稿通常该砍掉一大半）：

| 删什么 | 判据 |
| --- | --- |
| 与主线无关的段落 | 删掉它，主线会不会断？不会 → 删 |
| "我也试过但没成"的过程 | 除非**它的失败有信息量**（别人会踩同一个坑），否则删 |
| 重复表述 | 同一个意思说了两遍 → 留讲得清楚的那遍 |
| 防御性铺垫 | "由于时间有限""仅供参考" —— 除非真的影响结论，否则删 |

**补**（读者需要但你默认他知道的）：

- **前置条件**：他得先有什么（版本、权限、前置知识）
- **一个最小例子**：抽象讲完必须给一个具体的（"例如……"）
- **局限**：什么情况下**不适用**。写了局限反而更可信 —— 只讲好处的段落，读者会自动打折
- **可复现要素**：版本、环境、测量方式（数值类断言必须带，否则不可复核）

> ⚠️ **知识诅咒**：你刚做完这件事，已经忘了"不知道的人卡在哪"。补前置不是啰嗦，是唯一能对抗它的办法。

---

## 5. 拆篇：什么时候该分成两篇

**总判据**：**读者会不会"因为读了 A 才需要读 B"？**
不需要 → **该拆**；需要 → **留一篇**（或把 A 压成 B 的开头一段）。

**满足任一条，通常就是两篇：**

1. **标题写不出来** —— 必须用"与""及"连接两个并列名词才能概括；
2. **"所以呢"有两个** —— 两个互不支撑的答案回答"读者该记住什么"；
3. **砍掉一个话题，文章依然完整**。

**三种不该拆的情况：**

- 拆完每篇都撑不起一篇像样的长度，读者要跳来跳去才拼出全貌；
- 两篇共享大段前提（每篇都要重复同一段背景）；
- 拆的理由是"我想写得更细" —— 那不是拆篇，是**这一篇就该写细**。

**决定要拆，按什么轴切**：

| 切法 | 何时用 | 例子 |
| --- | --- | --- |
| **按读者任务** | 读者目的不同（最常用、最稳） | 《怎么跑起来》/《为什么这样设计》 |
| **按问题** | 一个主题下的独立问题 | 《光照性能》/《内存占用》 |
| **按版本/时间** | 内容随版本变 | 《5.7 的做法》/《5.6 及以前的坑》 |
| **按深度** | 入门 vs 深入 | 《30 分钟接入》/《源码级原理》 |
| ❌ **按内容类型** | 几乎总是错的 | 《代码部分》/《截图部分》 |

> ⭐ **不要一开始就决定分几篇。** 先按"一篇"写，**写到 40% 左右主线自然显形**，那时再拆成本最低。
> **拆篇红利**：素材账本本来就是**按问题分组**的 —— 拆篇 = 把问题分给不同文章，**素材一行都不用重写**。

## 6. 留痕：校对版与发布版

正文里的 `〔A-01〕` 这类角标（**全角六角括号**），**保留在校对版，发布版隐藏**。两版同源，只差显示层。

| 版本 | 用途 | 角标 |
| --- | --- | --- |
| **校对版** `04_草稿.md` | 自查、复述测试、交付给独立读者评审 | **保留** —— 每个断言能翻回账本 |
| **发布版** `06_发布版.md` | 给读者看的成品 | **隐藏** —— 别让角标干扰阅读 |

⛔ **角标语法**：`〔A-nn〕`／`〔B-nn〕`／`〔C-nn〕`，**全角六角括号**（U+3014/U+3015），**紧贴前一个字符**。
**不用半角 `[A-01]`** —— 方括号在代码里到处都是（`delete[]`、`assets[].sha256`、`parts[]`、Markdown 链接 `[text](url)`），**任何以半角方括号为锚的正则都会误伤**。实测过一次：作者用正则隐藏角标，把正文三处 `[]` 一起吃掉，**内容损伤，靠两版逐行对照才发现**。

⛔ **隐藏的方式是「跑脚本」，不是「自己写正则」**（v0.4）：

```
node tools/publish.mjs --draft 04_草稿.md          # 生成 06_发布版.md
node tools/publish.mjs --verify 04_草稿.md 06_发布版.md   # 机检不变式
```

**不变式**：`publish(04_草稿.md)` 与 `06_发布版.md` **逐字节相同**。不同 = 发布版被手改过，或有转换漏项 → **major**。**改稿只改草稿，然后重跑转换；永远不要直接编辑发布版。**

> ⚠️ **别为了"发布版干净"在采集时省掉 ID** —— 角标是验收能机械化的前提（"每条断言能查到出处"可以写成可运行检查）。代价用**分版**解决，不用字段妥协。

## 7. 规则表

| ID | Class | Knowledge |
| --- | --- | --- |
| `WRC-01` | `reviewed_invariant` | 落笔前必须能用一句话写出"本文承诺让谁做什么"。写不出即视为尚未完成重构，不得进入成文。 |
| `WRC-02` | `reviewed_invariant` | 素材来自多处、或按采集顺序堆叠时，必须先重排再写；直接按采集顺序成文视为未通过。 |
| `WRC-03` | `reviewed_invariant` | 每条因果陈述必须在素材里有对应证据。仅有"两个事实并排"的，必须降级为并列陈述或补证据。 |
| `WRC-04` | `reviewed_invariant` | 不得把两个各自为真的断言并置以暗示第三個结论（两者都没说的那个）。发现即视为未通过。 |
| `WRC-05` | `reviewed_invariant` | 首屏（标题 + 开头两段）必须让读者能判断"这跟我要做的事有没有关系"。做不到就重排。 |
| `WRC-06` | `craft_default` | 术语首次出现时就地解释，而不是集中列术语表 —— 后者治症状，前者治因。 |
| `WRC-07` | `craft_default` | 草稿默认要砍。判据：删掉它，主线会不会断？不会就删。 |
| `WRC-08` | `reviewed_invariant` | 数值/性能类断言必须带可复现要素（版本、环境、测量方式）；缺一项即视为未通过。 |
| `WRC-09` | `craft_default` | 必须写"什么情况下不适用"。只讲好处的段落，读者会自动打折。 |
| `WRC-10` | `structural_invariant` | 校对版必须保留 `〔A-nn〕` 角标（**全角六角括号**，紧贴前字）；发布版必须隐藏，且**隐藏方式是 `tools/publish.mjs`**，不许自己写正则。**不变式**：`publish(04_草稿.md)` 与 `06_发布版.md` **逐字节相同**（`publish.mjs --verify` 机检）；不同即视为未通过。<br>⛔ **角标不得单独占一个表格单元格**（v0.5 补 —— 实测撞出来的）：`\| 〔A-01〕 \|` 这种写法，角标删掉后**整格变空**，表格结构坏掉。<br>**修法（两条都行）**：在表格里把引用写成「依据 `A-01`」这种**纯文字**；或把角标**紧贴在该格已有的文字后面**。<br>⚠️ `publish.mjs` 的 `sanity()` 对空单元格**只报 advisory** —— **它报警，修法在这里**。<br>⛔ **跨册引用必须带册名**（v0.5 补 —— 账本分册逼出来的）：一本账装不下时 `wiki-collect` 允许拆成多册（`素材账本字段.md` §3「装不下就拆专题，**不要扩位数**」），**各册的 `A-01` 是三个不同的东西**。角标写成：<br>· `〔A-01〕` —— 主册 `01_素材账本.md`（**册名可省**，绝大多数引用都是它）<br>· `〔01b A-01〕` —— `01b_素材账本-续.md`<br>· `〔02 A-01〕` —— `02_素材账本-Q5Q6.md`<br>**册名 = 文件名的第一段**（下划线之前）。⛔ **不许自创前缀**（如「续 A-01」）—— `COL-S16` 明令禁止，而且 `publish.mjs` **删不掉它**：实测一轮作者只能这么写，结果**吃 35 条 advisory**，角标原样出现在发布版里给读者看。 |
| `WRC-11` | `reviewed_invariant` | 拆篇前必须满足三条硬信号之一（标题写不出／两个"所以呢"／砍掉它仍完整），否则不拆。 |
| `WRC-12` | `reviewed_invariant` | 拆篇禁止按"内容类型"切（《代码部分》/《截图部分》）；按读者任务、问题、版本或深度切。 |
| `WRC-13` | `craft_default` | 不要在动笔前决定分几篇；写到约 40% 主线显形后再定。 |
| `WRC-14` | `taste_option` | 用什么句式做过渡、开头用陈述还是提问 —— 不判。 |
| `WRC-15` | `craft_default` | 删"我也试过但没成"的过程，除非那个失败本身有信息量（别人会踩同一个坑）。 |
| `WRC-16` | `structural_invariant` | **交叉引用只指章节号或 ID，不指措辞；跨文件引用必须写出文件名。** 条件：正文/文件之间互相指路时。要求：写成 `见 <文件名> §N` 或 `见 <ID>`；禁止 `见下"某某"` 这类**引用措辞**的写法。例外：同一文件内的相邻小节可以写 `见下`，但**必须带节号**。⚠️ 理由：措辞会被改写，章节号不会 —— 而**断链不会报错**，它只是悄悄指错地方。 |
