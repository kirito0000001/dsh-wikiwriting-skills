# 规则契约（`wiki-collect`）

> **本文件是规则正文的唯一处。** 其它文件与 SKILL.md 只许引 ID，不许复述规则条文 —— 复述一次，就会有两处需要同步。
> 改一条规则 = 改本文件一行；**改 ID 或级别算破坏性变更**，必须同时回改引用它的文件。
> 规则分级词汇借自 MIT 许可的 `zenstory-ai/drama-skills`；**下面每一条的条文都是我们自己写的**。

## 0. 判定者由级别决定

| 级别 | 谁能判 | 能不能阻断交付 |
| --- | --- | --- |
| `structural_invariant` | **脚本**（确定性检查） | 能，退出码即门禁 |
| `reviewed_invariant` | reviewer（人／独立实例），**必须引证据** | 能，但要给证据 |
| `craft_default` | 作者；**说明理由即可覆盖** | 不能（要覆盖必须先写理由） |
| `taste_option` | 不判 | **不得单独阻断** |

⚠️ **v0.4（2026-10-07）起执行者已存在**：`tools/check.mjs`（零依赖 node，自带自检）。⛔ **实现清单不在这里手抄** —— 跑 `node tools/check.mjs --implemented` 看当前值。
> ⚠️ **这一行原本逐条列着那份清单，而它漂过两轮**（v0.5 治本）：
> · v0.4 漏了 `S09`／`S16`／`R12`／`R17` —— **脚本早就实现了，是清单没跟上**；
> · 加了 `COL-S17` 之后，**四处副本一处都没改**。**同一处漂移在 `SKILL.md` 与 `完成判据.md` 里各犯过一次。**
> ⛔ **而且那份旧清单混了三个概念**：① 会 `report` 出来的**检查项** ② 只作"纪律"被引用的（`S08`／`S15`／`S16`／`R17`）③ 声明"不负责"的 ——
> 旧清单把 ② 也列成"已实现"，而 `COL-R01` 一边被声明"不负责"、**一边真的在报**。**自相矛盾。**
> ✅ **现在真值只在 `check.mjs` 的 `IMPLEMENTS` 一处**，自检拿它和**源码里真正 `report` 出来的集合**对撞；**任一侧多出或缺少都报 `SELFTEST_FAIL`**（已做注入测试：2/2 抓到）。
级别描述的仍是「**可**被脚本阻断」；**没有被 `check.mjs` 实现的那几条第一级规则，仍不得声称「脚本已过」**。
> v0.3 这里写的是「执行者尚未实现」，而 `COL-C18` 同时要求「技术专题交付前自带一个能跑的检查脚本」—— 两条并排时语义含混：交付物里到底该不该有脚本？实测一轮之后定案：**该有**。v0.3 那句话指的是**技能自己**没提供执行者，不是「专题不该写脚本」。见 §5。

**三条硬边界**：
1. **脚本只能守第一级。** 把 `craft_default` 当阻断执行「是差两级」。
2. **绝不用固定词表或形容词比例阻断交付** —— 那是把上下文判断变成脆弱规则。
3. ⚠️ 一个必须写清的例外：**闭集枚举可以机检**（`COL-S04` 五值状态、`COL-S05` 十四词关系）。判「值在不在已声明的枚举里」是确定性检查；判「这段文字像不像某类」是语义猜测。前者可机检，后者永远不可。**枚举必须写在唯一一处**（本文件），不许硬编码进脚本。

## 1. `structural_invariant`（脚本可阻断）

| ID | 规则 |
| --- | --- |
| `COL-S01` | 编号 `A-nn`／`B-nn`／`C-nn` **不得回收**：删掉之后该号作废，不重用于新条目。<br>⛔ **编号只许两位**（`A-00`…`A-99`）—— **每级上限 99 条**。三位编号（`A-100`）**不在语法内**。<br>⚠️ 这条以前只写「`A-nn`」，**没人把它读成"上限 99"** —— 实测一份 **324 条**的合并稿：检查器只解析到 **98 条**，**226 条无声消失**，而且报 `major=0`、**退出码 0**。**正确做法是拆成多个专题**（每个 ≤99 条），**不要扩位数**。<br>⚠️ **作用域仅限「账本条目编号」，不管文档小节号** —— 小节号见 `COL-S14`。把这条套到 `## n.`／`### n.` 上会大面积误报：实测一份 17 条小节的文档因此报出 **16 条误报（94%）**。<br>⛔ **「拆」是规范允许的正路，不是权宜之计**（v0.5 补 —— 原文只说"拆成多个专题"，**没给分册的语法**，属于 §5.1 的「只给词不给语法」）：<br>· **主册** `01_素材账本.md`（**必须存在**）<br>· **续册** `01[a-z]_…素材账本….md`（`01b_`／`01c_`…）<br>· **续册** `02[a-z]?_…素材账本….md`（`02_`／`02b_`…）—— ⛔ **必须含「素材账本」四字**，因为 `02_` 在虚构类是设定表位<br>**每册的 `A`／`B`／`C` 编号各册独立**（各自 `01…99`）—— **所以引用别册必须带册名**：`〔A-01〕`（主册，**册名可省**）· `〔01b A-01〕` · `〔02 A-01〕`（完整语法见 `wiki-write` 的 `WRC-10`）。**册名 = 文件名的第一段**（下划线之前）。<br>⚠️ **「源表登记」跨册共用** —— 多册是**一个逻辑账本**：主册列全表，续册可只列本册用到的。<br>⚠️ **实测代价**（`fantasyproject`，144 条）：拆了之后**引用形态／分册命名／检查器／源表登记四处全出问题** —— 因为当时**除了"拆"这个动作，什么都没约定**。<br>⛔⛔ **拆册的触发判据不是「活条目到 99 条」，是「号位用尽」**（v0.5 再补 —— 又一轮实测撞出来的）：<br>**可用号位 = 99**，而**作废的号仍占位**（不得回收，见本条开头）→<br>**号位占用数 ＝ 活条目数 ＋ 作废号数**。**这个数到 99 就必须拆**，哪怕活条目只有 92 条。<br>实测：一轮作废 16 个号后剩 **92 条**活条目 —— **99 个号位已全部占满，再加一条都加不进**，只能往父条目上追加。<br>→ **所以「拆」要在还有余量时就做，别等到写不下。**（上一版只写了"怎么拆"，没写"什么时候必须拆" —— 又一处 `§5.1` 的「给了动作，没给触发判据」。） |
| `COL-S02` | `引用路径` 的**正式语法**（v0.4 定义；v0.3 只写「三段式，允许嵌套」，实测三件真实写法全被判错）：<br>`引用路径 := 路径项 ( "；" 路径项 )*`<br>`路径项   := 源表名 "[" 主键 "]" 尾段? 尾注释?`<br>`尾段     := ( "." 段名 \| "[" 下标 "]" )+`<br>`尾注释   := "（" 任意非「）」字符 "）"`<br>· **多值**用全角 `；` 分隔（不用 `,`、`、`、空格）<br>· **尾段可省** —— `launcher[ScriptFileName]` 合法，主键本身就是被引的那一项<br>· **尾注释**只在最后一个路径项之后，全角括号<br>· 反引号包裹可选<br>· ⛔ **`[]`（空方括号）不是合法下标** —— 它是「角标隐藏误伤正文」的哨兵，命中即报<br>· `源表` 必须在账本的「源表登记」里**唯一解析到真实位置**。<br>· ⛔ **`源表名` 用 ASCII 短代号**（`rd`／`ctx`／`gm`／`oral`）—— **v0.5 补**：v0.4 的语法里 `源表名` **没限定字符集**，**这正是"只给词不给语法"**（§5.1 要防的）。实测代价：一个专题用中文「口述」当源表名，**一次吃 7 条 `COL-S02` major** —— 因为**现有检查器的正则只认 ASCII**（`/^`?([A-Za-z_][A-Za-z0-9_]*)\[([^\]]+)\]/`）。之前所有专题都用短代号，**这个洞从没暴露过**。⚠️ **中文不是"非法"，是"会让 `引用路径` 变长易错、且和现有执行者对不上"** —— **要么改执行者、要么改名字；实测那轮选了改名字。**<br>⚠️ **「真实位置」可以是未入库的工作区文件**（实测有专题把两份被 `.gitignore` 排除的草案登记为源表，这是合法的）—— 但**必须在登记表里注明「工作区文件，未入库」**，否则读者拿不到这份材料，**引用就不可复核**。检查器对「文件不存在」只报 advisory，正是为此。 |
| `COL-S03` | 日期一律 `YYYY-MM-DD`，**不加引号**。 |
| `COL-S04` | `状态` 只许五值：`一手已核`／`自测`／`二手线索`／`待复审`／`已推翻`。 |
| `COL-S05` | 关系列只许 **18 词**闭集（见 `采集-剧本与设定.md` §2；v0.5：12 → 14 → 18）。<br>⛔ **关系表只收「结构关系」—— 事件不进关系表**。判定式：**能写成「A 是 B 的 ___」→ 结构关系；只能写成「A 对 B 做了 ___」→ 事件**，归时间线／事件表。<br>⚠️ 实测：一次虚构材料撞出 **15 类**「塞不进闭集」的关系，逐条分下来**只有 4 类是真的结构关系**，**7 类是事件**、3 类是机制／因果、1 类是属性。**当时差点往闭集里塞 15 个人际词 —— 而加判据比加词重要得多。** |
| `COL-S06` | `矛盾` 字段与可见的 `#### 未决` 小节**必须两侧对齐**：有字段无小节 → 报警；有小节无字段 → **失败**。 |
| `COL-S07` | 每次校验**先算「本次实际检查了多少单元」**；低于期望值直接报 major `PARSE_EMPTY`，**不许以退出码 0 放行**。输出永远带一行 `checked: N fields, M refs, K invariants`。 |
| `COL-S08` | 悬空引用只扫**活区**。**活区的判定**（v0.4 定义；v0.3 只说「显式标记的活区」而全库没有任何标记语法，作者只好自己把「缩进的字段行」当活区）：<br>· **账本**：条目字段行（`- 字段：值`，含 `｜` 分隔的后续字段）与「源表登记」表行<br>· **文档**：正文段落与列表项<br>**无条件跳过**：① 围栏代码块（` ``` ` / `~~~`）整块；② 标题含「示例／反例／模板／写法／样例／占位」的小节整节；③ 文档里**源表名未登记**的反引号 token（否则 `delete[]`、`parts[]`、`assets[].sha256` 这类正文代码会被当成悬空引用）。<br>**被跳过的引用必须计数打印**（否则退化成「跳过一切 = 全绿」）。 |
| `COL-S09` | **数值不变量**被破坏 = **major**（禁止降为 advisory）。<br>**语法**（v0.5 定义 —— v0.4 只写了「单调性／范围／单位／基数」四个词，**既没语法也没执行者**，于是「三查」实际只有两查）：写在 `02_设定表.md` 的「数值表」小节内，**位置不限**，一行一条：<br>　`- 阶梯单调：<对象1> < <对象2> < …`<br>　`- 倍数关系：<对象>｜<属性> = <正数> × <对象>｜<属性>`<br>**四类**：`INV-RANGE` 区间自洽（`值` 写成 `a～b` 时必须 a ≤ b）／`INV-UNIT` 单位一致（同一 `对象｜属性` 的真单位唯一）／`INV-LADDER` 阶梯单调／`INV-SCALE` 倍数关系。**前两类不需要声明，后两类需要声明。**<br>⛔ **`源未标注` 是哨兵不是单位**，不参与单位比较 —— 否则「一行标 `%` 一行标 `源未标注`」会被误报成冲突。<br>**档位故意三处不对称**（理由同 `COL-S08`：拼写差异不值得拦交付）：不变量**被破坏** → major；声明**语法不对** → advisory；声明的操作数**在表里取不到** → advisory。<br>⛔ **`（本子专题无）` 是空态标记，不是解析失败** —— 真实语料里 **18 处**，是 `split_tables.py` 自动生成的。认不出来就会把每个拆出来的子专题报红（**实测踩到**：`剧情人物-身世/02_设定表.md:26`）。参考实现有**同一个 bug**，只是它只跑合并稿，从没走到这条路上。<br>**作用域**：只作用于 `02_设定表.md` 里**表头含 `对象`／`属性`／`值` 三列**的表，范围到下一个同级或更高级标题为止。**没有 `02_设定表.md`（技术专题）→ 不适用**，这与「解析到零」是两回事，退出码与消息必须能分开。<br>⛔ **每一类必须分别计数打印**（`range`／`units`／`ladder`／`scale`）—— 参考实现在 778 行上报 `found 0`，却没说区间匹配到几个；一个都没匹配上的话，那个 `0` 就是假绿灯（`COL-R17`）。 |
| `COL-S10` | `定位` 一行多条时用 `；` 分隔。 |
| `COL-S11` | **不得新建进度／生命周期文件**；`_` 开头、`00_`–`09_` 前缀、`{{…}}` 是保留字（大小写不敏感）。 |
| `COL-S12` | 结构识别**不得建在字面英文关键词上**（中文文档里那是「永远零发现」的假绿灯）；识别失败即报错，不许静默放过。 |
| `COL-S13` | 命名：字段名一律 `snake_case`；类型／表名加类别前缀且**全局唯一**（不自造 `Tb` 前缀）；集合用复数、单值用单数。 |
| `COL-S14` | **文档小节号**：`#`–`######` 标题若带编号（`1.`／`1.1`），**同一父节点下的同级标题不得重号**。比较用「**标题路径**」：有编号用编号、无编号的父节用标题文字，逐级拼成 `3.1` 这样的全路径，**只比全路径**。<br>⛔ **必须无条件跳过围栏代码块** —— 代码块里的 `# …` 不是标题。漏跳的后果是**漏报**（不是误报）：实测一次，代码块里一行 `# 4) 自检…` 被当成 H1 污染了标题路径，于是「两个 `## 13.`」这条真缺陷**从报告里消失**，界面显示全绿。<br>⚠️ 只管**文档**；账本条目编号见 `COL-S01`。 |

| `COL-S15` | **检查器自检**：任何检查器（`tools/check.mjs` 或专题自带的）**必须内置「已知必须报」的负样本，并在每次运行时先跑它**。负样本没被报出来 = 检查器失效 = **major**，且**本次结果一律作废**（不能因为 `major` 计数为 0 就放行）。负样本要覆盖**每一类**检查（引用／编号／日期／枚举／不变量），不能只覆盖一类；同时要有「必须**不**报」的正样本，因为**误报比漏报更伤**。<br>**为什么单独立一条**：`COL-S07` 只保证「解析到零」被发现，**不保证「计数正常但结论是错的」被发现**。实测一次：`docs: 13 files, 181 headings` 计数完全正常，而结论是错的 —— 真缺陷被漏掉，报告显示 `major=0`。没有负样本的 invariant 是装饰（§5），而**没有负样本的检查器，它的「全绿」同样没有信息量**。 |
| `COL-S16` | **`定位` 的写法（v0.4 定义 —— 与 `COL-S02` 同一个病根：只给词不给语法）**。只许这四种形态：<br>· `文件:行` —— 单行（**`Src/Config.h:42`**，**路径必须带目录**）<br>· **`文件:起-止`** —— 行区间，**用半角连字符**（`Push-ServerBranch.ps1:266-272`）<br>· `URL` ／ `URL#anchor`<br>· **符号名**（函数／类／常量名）<br>⛔ **不许自造前缀**（实测有人写过 `:266-L272`，`L` 是自创的）。一行多条用全角 `；`（`COL-S10`）；尾随注释用**全角括号**。<br>⛔ **路径按「仓库根」解析，所以必须带目录**（v0.5 补 —— 实测代价 **20 条 advisory**）：裸文件名 `Config.h:42` **解析不到**。示例改成裸名就会教出这个坑 —— **v0.4 的示例就是裸名，已改。**<br>⚠️ 解析顺序：**先切尾注释、再剥反引号** —— 顺序反了会解不出来（实测：`` `path:1`（备注） `` 形状产生过 2 条误报）。<br>**检查器纪律**：解析不了的定位**必须计数打印**，不许静默跳过（`COL-S08`／`COL-R17`）。 |

| `COL-S17` | **口述来源的条目，`证据` 必须是口述记录的逐字子串**（v0.5 新增 —— 「问作者」这条路进来的条目）。<br>**条件**：该条目的 `定位` 指向 `_src/作者口述.md`。<br>**要求**：`证据` 里引的那句话，必须能在 `_src/作者口述.md` 里**逐字命中**；`复审周期` 必须填（**作者是活源**，见 `COL-R03`）。<br>**为什么可机检**：账本里的引文 ↔ 口述记录里的原文，是**两份文件之间的字符串包含关系** —— 与 `COL-S02` 的主键字面命中同构。<br>⛔ **它拦的是转述**：把「不会公开」转述成「没有」，字符串当场不匹配。**这正是这条路上最容易出的错。** |

**为什么 `COL-S12` 是硬规则**：实测过一份中文字段表让校验器解析出 **0 个表**，随后 `major=0`、退出码 0 —— 判「可以交付」。工具自己的原则写着「不做静默漏检」，但这一格没落地。

## 2. `reviewed_invariant`（凭证据判，reviewer 判定）

| ID | 规则 |
| --- | --- |
| `COL-R01` | `断言` 必须**能被判真假**。「它支持自定义配置」「性能提升明显」不是断言，是评价。 |
| `COL-R02` | `状态` 描述的是「**断言是否忠实于来源**」，不是「世界上是否为真」。来源本身说得对不对，用 `矛盾`／`未决` 处理，**不用状态字段**。<br>⛔ **判据的锚点是「断言的对象」，不是「材料的作者」**（v0.4 补 —— 实测最贵的一处被迫猜）：<br>· 你读的那份材料里**逐字写着**你要断言的那件事 → `一手已核`<br>· 材料**转述**了第三方行为／外部事件，而你没读到那个一手的 → **`二手线索`，即使那份材料是你自己写的**<br>⚠️「我们自己仓库里的文档」**不等于**「一手」。判据问的是「**这条断言的对象，被你实际读的那份材料直接证实了吗**」。<br>实测：一轮里 2 条「第三方软件内部行为」（来源是自家一份未入库草案）被降级为 B 级，另有 5 条「主体是自家怎么绕、注解是第三方行为」的**半二手**条目判成一手 —— 作者自述「换个人可能判成二手」。**这条口径就是为了消掉这个自由度。** |
| `COL-R03` | `复审周期` **仅「外部活源」必填**；内部断言填 `时效：none`（时间不是变量）。<br>⚠️ **「作者口述」是活源的一种**（v0.5 补）—— 他会改主意，所以口述来源的条目**必填 `复审周期`**，并写 `失效条件`（事件，不写时间）。 |
| `COL-R04` | **读源文件得来的断言必须能解析到 `钉死`**。取值闭集（v0.4 定义；v0.3 只写「commit／tag／版本号」，**材料是未提交的工作区时没有合法取值** —— 实测一轮 37 条 A 级一条都填不出来，作者只好自定口径并记成缺口）：<br>`commit:<7–40 位十六进制>` ｜ `tag:<标签>` ｜ `版本:<semver>` ｜ `工作区@YYYY-MM-DD`（有未提交改动时追加 `+未提交`）｜ **`快照:YYYY-MM-DD`**（v0.5 新增）<br>**两种书写方式**：① 条目里逐条写 `- 钉死：<值>`；② **全篇声明一次** —— 顶格写一行 `钉死口径：<值>`（值可写在同行，也可写在**其后 3 行内**），条目即可省。<br>⛔ 条目写 `同上` 时，全篇必须存在可解析的 `钉死口径：` 声明；解析不到即 major。<br>⛔ **`commit:`／`tag:` 要向上找最近的 VCS 根**（v0.5 补 —— 实测撞出来的）：材料在被采仓库的**子目录**里时，子目录自己没有 `.git`，**外层仓库有** —— 用外层的 commit。实测一轮只查了子目录、判定"材料不是仓库"，**白白丢掉了合法的钉死值**。<br>⛔ **`快照:YYYY-MM-DD` 给「完全不在任何 VCS 里」的材料**（散文件／导出稿／`.docx`／没有外层仓库的目录快照）—— 前四种一个都填不出来，实测一轮虚构材料的作者只能临时写 `版本:1.0` 顶。**用 `快照:` 时全篇声明必须列被采文件清单（`文件名｜字节数`）**，否则"哪一版"仍不可复核。 |
| `COL-R05` | `证据` 够核对即可，**不得整段抄原文**。 |
| `COL-R06` | **未核实不得与已核实混放** —— 状态字段就是为此存在。 |
| `COL-R07` | **不为「以后可能有用」收集**，只收服务于选题卡问题的材料。这是采集失控的头号原因。 |
| `COL-R08` | `已推翻`／`已解除` 条目**永久保留，不得删** —— 它们是防止重复踩坑的资产。 |
| `COL-R09` | B 级 `影响` 只填**消费动作**（「正文只能写'有报告称'」／「必须去核一手」），**不许填内容评价**。 |
| `COL-R10` | 两源相争**必看提交历史**，并按裁决顺序表定案（见 `冲突裁决.md`）。 |
| `COL-R11` | 别名归一化放在**合并阶段**做；合并前**回原文核「疑似矛盾」**，不靠子代理的转述。 |
| `COL-R12` | 读代码得来的断言必须能指到 **`文件:行` 或符号名**。 |
| `COL-R13` | `已推翻` 的结论**正文删错误、账本留错误** —— 两件事分开管，不许用一条规则覆盖两边。 |
| `COL-R14` | 数值表**零自然语言**；正文里的精确值只走 `引用路径`，自由写只许写意图与量级。 |
| `COL-R15` | 交付必须有 **0 个 major**；「解析到零」算 major。 |
| `COL-R16` | 输出叫「疑似」不叫「违规」，判决权留给人；每条 finding 给 **`文件:行` 或小节锚点**（不能只到文件）。 |
| `COL-R17` | 任何「该查而没查」都要显式打出 `*_SKIP`／`*_UNPARSED`，**并计入 `COL-S07` 的已检查单元数**。 |
| `COL-R18` | 加任何新标签／新字段前先做准入测试：**「这个标签会改变什么行为？」** 不改变行为的是装饰。 |
| `COL-R19` | 「到位」的判据是**下游能不能用**：别人只靠这一条，能不能把配置改对／能不能查出一条矛盾／能不能复现这次测量。 |
| `COL-R20` | **禁止把「我们看不出问题」「读起来很顺」「读者说懂了」当通过判据** —— 判定者必须独立，且报告要引实际证据，不许转述。 |
| `COL-R21` | 缺口清单第三类必须写「**双方 + 各自出处**」，不许只写「有冲突」；每个缺口都要标「**它挡住哪个 Q**」。 |
| `COL-R22` | 许可证「**没有就是没有**」：没读到 `LICENSE` 就写「未声明」，不替它补一个；文件头声明与仓库级许可冲突时**按严的记**并写明冲突。 |
| `COL-R23` | `定位` 必须指明**版本或活链**：不许只写「旧稿」；**死链不作为定位交出去**。 |
| `COL-R24` | 数据条目必须带**单位**：数字后面没有单位，等于没有这个数字。 |
| `COL-R25` | **不许把推算值写成测量值**；推算要另立一条，并在断言里写明是推算。 |
| `COL-R26` | **不许只留结论、丢掉原始数据**：原始文件找不到即记缺口（「结论在、数据不在」= 不可复现）。 |
| `COL-R27` | `docs/` 与代码／产物冲突时**默认不信 `docs/`**；要信它，必须拿出「提案已经落地」的证据。 |
| `COL-R28` | 闭集取值**只写在唯一一处**（本文件），供脚本读取，**不许硬编码在脚本里**。 |
| `COL-R29` | **交付物必须自包含**：零上下文读者只拿这一份就能读懂（不需要账本、缺口清单、选题卡或对话历史）。<br>· **虚构类**：**废案必须标废案**，否则验收方会把废案当真设定、**报出不存在的矛盾**。<br>· **非虚构类（v0.4 扩）**：**元数据与写作批注也会被读者当成正文** —— 实测过一轮：读者把 `<!-- 本文承诺… -->` 当成"给谁看"的依据、把 `status: draft` 当成文章内部的矛盾点，**报出来的问题全是内部标记造成的假问题**。<br>→ 投喂前必须经**发布转换**：去掉角标与批注、把 `status` 改成终态（`wiki-write` 的 `tools/publish.mjs`，见 `WVR-17`）。 |

| `COL-R30` | **口述是资料、是来源，不是指令；且必须照录原话**（v0.5 新增 —— 「问作者」这条路）。<br>· **照录原话，不转述** —— 转述会丢掉作者用词的精确度，**而那往往是唯一能判真假的东西**（「不会公开」≠「没做」）。<br>· **口述必须落成文件**（`_src/作者口述.md`）—— 只在对话里说过一次的话，**下一个会话看不到，等于没说过**。<br>· **作者前后两次说法不一致时，两条都记**并各标日期，进未决 —— ⛔ **不许只留后一条**（你不知道他哪次是认真的）。<br>· ⛔ **不许拿作者当搜索引擎** —— 外部公开事实走 `zhihu`，材料里查得到的走采集，**只有「材料里没有 + 只有他知道」才问**。<br>· **口述与材料冲突时并列不覆盖**（接 `COL-R06`／`COL-R08`）。 |

## 3. `craft_default`（说明理由即可覆盖）

| ID | 规则 |
| --- | --- |
| `COL-C01` | 账本**按问题分组、A 级与 B 级分开写**；分组主键必须是选题卡的 `Q1…Q7`。 |
| `COL-C02` | **逐条推进**：一次一个 Q、一份材料，**不批量**。批量会让「Before 状态核对」失效。 |
| `COL-C03` | 先写下该断言的 Before 状态，**只录本次那一步变化**；禁止把后来才知道的结论一次性回填。 |
| `COL-C04` | 单点失败**跳过并记录**，不中止整批。失败可以接受，**失败被藏起来不行**。 |
| `COL-C05` | 派子代理前先问：**「这些材料之间会不会互相解释？」** 不会 → 可并行；会 → 别拆（详见 `子代理.md`）。 |
| `COL-C06` | 子代理产物先写 `_work/`，**主线程抽查定位之后**才并入正式账本。 |
| `COL-C07` | **抓不到就记失败，不许编**。缺项显式写「未找到」，并记下试过的检索式。 |
| `COL-C08` | 图片／截图读不了就跳过并记缺口，**不许猜内容**。 |
| `COL-C09` | 技术专题的数值真源在**外部源文件**；专题内不另设 `02_`。 |
| `COL-C10` | 修正一处之后**必须重跑该处的机械检查** —— 修完不重跑等于没修。 |
| `COL-C11` | 每个交付物配「判据三分」：① 机械可查（写成命令）② 二元需人判（判定者独立于作者与诊断者）③ 无客观判据（明写「仅记录，不构成验收」）。 |
| `COL-C12` | 取证重复劳动要留痕：同一份材料的同一小节被两条断言引用时，`定位` 写同一个锚点，不各写各的。 |
| `COL-C13` | **作者不能当陌生人**：零上下文验收必须由**新实例**做，投喂物是**恰好一份自包含文件**（设定条目 = 条目 + 设定表快照），**不投喂**账本／缺口清单／选题卡／对话历史。 |
| `COL-C14` | **传给子代理／验收方的设定表快照必须带「源文件 + 时间」** —— 这样它才分得清哪条是废案、哪条是现行（`COL-R29`）。 |
| `COL-C15` | **诊断者 ≠ 确认者**：改变含义的修改必须由独立实例确认；**机械可查的重跑那条检查即可**，不需要第二个实例。 |
| `COL-C16` | 跨作品并行时，**三份产物必须同构**（同一套表、同一套字段、同一套列顺序）—— 不同构就合并不了，这条要在提示词里写死。 |
| `COL-C17` | 给子代理的输出**只能是账本条目**，**禁止散文总结**（总结丢定位，而定位是这份产物唯一的用处）。 |
| `COL-C18` | 技术专题交付前**自带一个能跑的检查脚本**（零依赖 node 优先）。<br>⛔ **放哪（v0.5 补 —— 实测撞出来的）**：**`<专题目录>/check.mjs`，裸名，不建 `tools/` 子目录。** 技能原本**从没规定过路径**，而 `check.mjs` 的 `ALLOWED_TOP` 只放行裸的 `check.mjs`；实测一轮作者按「拿 `tools/check.mjs` 当底子」的字面理解放进 `tools/` → **必然吃一条 `COL-S11` advisory**（探针实测：`tools/` 报，`_tools/` 与 `_work/` 都不报）。见 `SKILL.md` §12.2。<br>⛔ **「拿它当底子」= 照它的「输出契约」写，不是照实现写** —— 它与 `COL-C24`（不许读 `check.mjs` 源码）**曾经对撞**，实测原话：「**不读一个 99683 B 的文件，却要照着它写一个新文件，这在物理上做不到。**」输出契约 = `selftest: OK（N 项断言，M 个夹具）` 的开头、`found N (major=… advisory=… info=…)` 的收口、`[级别] ID @ 文件:行` + `证据：` 的三段式、有 major 即退出码 1。 |
| `COL-C19` | 「支持 X」类断言**必须先证伪**：找实现分支／找占位标记／看默认值。**有字段 ≠ 有实现 ≠ 默认开。** |
| `COL-C20` | 闭集缺词（如「师徒」「血亲」）或未验证列（`不是`）**不许自行扩集／删列**：先记缺口与原句，试填一轮之后再统一决定。 |
| `COL-C21` | 术语表必须能指出该术语**首次出现的位置** —— 写作阶段才知道「首次出现前必须给定义」。 |
| `COL-C22` | **跨技能引用必须写「技能名/文件名」** —— 两个技能有**同名文件**（`SKILL.md`、`规则契约.md`），只写文件名会指错。实测过一次：一份反馈报告里的 `规则契约.md:30` 指的是本技能那一份，读的人先按 `wiki-write` 那份去核，行号对不上、差点当成报告写错了。 |
| `COL-C23` | **派子代理时编号段按「文件数 × 问题数」估，不按路数平分。** 段宽 ≥ `预计文件数 × 每文件断言数 × 1.5`，且段与段之间**留空档**。<br>⛔ 子代理**越界使用别人的号** = 违规，必须报回主线程改号，并记入「并入记录」。<br>实测：按「每路 10 条」平分，其中一路的任务是 **8 文件 × 3 问**，10 条根本不够，它为了覆盖每个文件**越界撞了另一路的号**，并入时被迫改号。 |
| `COL-C24` | **加载预算**：单次运行读技能文件**不超过 ~50 KB**。超了就说明**路由不准** —— 那是**要报的问题**，不是要硬读。<br>**三条省法**：<br>· `规则契约.md` 是**索引** —— **按 ID 查**，不要通读<br>· ⛔ **`tools/` 下的东西一律「跑，不读」**（**不只是 `check.mjs`**）—— 跑一次看输出，比读源码便宜两个数量级（⛔ **不写死字节数**：它从 v0.4 起涨了三倍，写死的数字第二天就过期）<br>· ⛔ **交付门需要的名字必须写在 `SKILL.md` 里**，不能只写在 `完成判据.md`（见 §12.1）—— 否则守预算的人**读不到它，却要拿它当门禁**<br>⚠️ 实测：一轮真实使用读了 **7 个文件 / 100,367 B（技能包的 85.7%）**，而 SKILL 写的是「按需加载、不遍历无关引用」。**那条规则当时是装饰。**<br>⭐⭐ **v0.5：这条预算第二次立功，而且方式是设计者没想到的。** 实测一轮的**必读集本身就超预算**：`SKILL.md` 13,679 + `采集-代码.md` 6,102 + `素材账本字段.md` 13,138 + `完成判据.md` 19,391 = **52,310 B > 51,200 B**。<br>→ 作者的处置是砍掉最大的 `完成判据.md`，**代价是交完都不知道「三查」是哪三查 —— 而 `SKILL.md` §12 正拿它当交付门。**<br>→ **修法不是抬预算**（抬到 55 KB 只是把问题往后推），而是**把交付门需要的两个名字搬进 `SKILL.md` §12.1**，让 `完成判据.md` 真正变成"按需读"。<br>→ ⭐ **教训：「必读集」这个词本身没有定义** —— 路由说"该读"、预算说"装不下"，**两边都没错，错在没人核对过它们加起来是多少。以后改路由或加文件时，顺手加一遍必读集。** |
| `COL-C25` | **专题目录默认建在被采仓库之外。** 建在仓库里会**污染被采仓库的 `git status`** —— 采集是只读操作，不许在被采对象上留下痕迹。 |
| `COL-C26` | ⛔ **昂贵／有副作用的动作要交出去判断**（v0.5 新增 —— 与 `COL-C25` 同一条思路，见 `SKILL.md` §8.2）。**凡是要在被采对象上产生副作用、或代价明显超出"读一遍"的动作，都不许 agent 自己决定做不做。**<br>**判定式（满足任一条即须交给用户）**：① **下载**（依赖／包／运行时／安装包／数据集）② **安装系统级组件**（Windows App Runtime、驱动、服务）③ **在被采对象里写文件**（构建产物、缓存、生成的报告）④ **长跑** —— 构建、测试、基准，超过 ~2 分钟。<br>**交出去时给三样（缺一不可）**：① **确切要跑什么**（原样命令，不许概括成"跑一下测试"）② **会下载／安装什么、大约多久** ③ **不做的后果**（交付物里会缺什么、会被标成什么）。<br>**用户同意 → 做；不同意／没回应 → 不做**，并**照录**那份材料（不要因为没跑就删掉），在**段首、段尾、"已知边界"头部三处**标明未验证，交付说明里**显式声明**放弃了哪条规则的合规。<br>⛔ **不许替用户决定"这个应该没关系"** —— 下载与安装是**在用户机器上留下东西**，那不在 agent 的权限里。<br>⭐ **与 `COL-C25` 合起来是一句话：采集是只读的，越界要报。**<br>⚠️ **实测**：一轮 README 专题的采集被约束为只读，作者自己推出了「命令照录 + 三处明写未实跑 + 声明放弃合规」—— **它做对了，但当时技能里没有这条规则**。 |

## 5. 覆盖与升级

- **覆盖 `craft_default`**：在该条目上写一行 `覆盖：<ID> <理由>`。**没写理由 = 违规**，不是覆盖。
- **改 `structural_invariant`**：必须同时给出「旧的负样本现在报什么」，否则不许改（防止为了过关而松规则）。
- **升级路径**：`taste_option` → `craft_default` → `reviewed_invariant` → `structural_invariant` 只许**逐级上升**，且每次上升都要配一个能真正拦住它的负样本 —— **没有负样本的 invariant 是装饰**。
- **执行者**：第一级规则的执行者是 `tools/check.mjs`。**新增／修改一条 `structural_invariant` 时，必须同时给它加一个夹具**（正样本：必须报；负样本：必须不报），否则它进不了自检，也就等于没有执行者（`COL-S15`）。

### 5.1 写规则时必须定义语法，不能只给词

一条规则如果要求「某种写法」，就必须给出**该写法的语法**（分隔符、可省部分、允许的字符、边界情形），否则每个执行者都会自己发明一套，且**互相判错**。

**实测代价**（2026-10-07 · winui 热更新专题）：接口在**三处**只给了词没给语法 —— `引用路径`「允许嵌套」、`钉死`「commit／tag／版本号」、「显式标记的活区」。后果是专题作者从零写的检查器第一版，在**自家账本上 7/7 全误报**、在靶子文档上 **17 条里 16 条误报（94%）**，四轮才收敛。

**判定式**：一条规则若出现下列任一形态，就是「只给了词」——
- 「允许 X」（没说 X 的边界）
- 「显式标记的 Y」（没给标记语法）
- 用斜杠并列一组取值（没说它们是不是闭集、能不能组合、有没有默认）
- 「必填」（没说**没有合法取值时**怎么办）

### 5.2 规则的作用域必须写明

`COL-S01` 原文只说「编号不得回收」，没说**作用域**。执行者把它自行扩展到文档小节号，于是 `## 3.` 下的 `### 1.` 与 `## 4.` 下的 `### 1.` 被判成重号 —— **16/17 误报**。

**判定式**：规则若含「唯一／不得重复／必须一致／不得回收」这类词，必须紧跟一句「**在什么范围内**」。

### 5.3 闭集的执行副本必须能发现漂移

`COL-R28` 要求闭集只写在唯一一处。脚本仍会需要一份执行副本（不可能每次都去解析 Markdown），所以 `tools/check.mjs` 的做法是：**启动时从本文件读回闭集，与内置副本比对，不一致即报 major `ENUM_DRIFT`**。这样「唯一处」是**可机检的**，不是一句自觉。

### 5.4 计数器的名单也必须能发现漂移（**踩出来的**）

§5.3 说的是「取值闭集」，**计数器名单是同一个病**：扫描器返回一份 counters，主流程另有一份 `totals` 白名单，两边漂移**无声**。

**实测**：`scanInvariants` 新增了 `inv-explicit-empty`，主流程的 `totals` 里漏登记 → `undefined + 1 = NaN` → `NaN > 0` 是 false → **那一格永远不显示，也不报错**。是读输出时肉眼发现的，不是任何检查发现的。

**修法**：合并计数器必须走 `mergeCounters()` —— 遇到未登记的键即报 major `ENUM_DRIFT`。**新增一个计数器 = 两处都要加**，漏一处会被拦下而不是变成 NaN。

⚠️ 这一类（**同一份名单写在两处**）在本项目里已经出现三次：闭集（§5.3）、字段名（`FIELD_NAMES`）、计数器。**每出现一次就加一道漂移检测，而不是加一句「记得同步」。**
