## 一、读旧稿（自己的旧文）

### 1. 只提断言，不搬段落

**旧稿等于自己的作品** —— 整段搬进新文是**自抄**，不是复用。规矩：

- 提取的是**断言**（一句能被判真假的话），不是句子。
- 每个断言都要能回溯到「**来自哪一篇、哪一段**」—— 这就是 `定位`。
- 原句只在**需要逐字对照**时以最小片段进 `证据`，**不得整段抄**（`COL-R05`）。

| 差（等于搬运） | 好（等于提取） |
| --- | --- |
| 把旧文第三节整段贴进账本 | `A-11｜状态：一手已核｜断言：GB/T 7714-2025 已现行、2015 版废止｜定位：旧文《引用规范》§3 第 2 段 ｜证据：openstd 检索输出 + 标准详情页（两个官方入口互证）｜拿到：2026-10-06｜核对：2026-10-06` |

### 2. 旧稿里的「错」要留，不要删

⚠️ **这里有一条必须写死的分岔**：**正文删错误，账本留错误**（`COL-R13`）。

- 旧稿里被推翻的结论，**新建一条 `已推翻` 条目**，写清**推翻理由 + 出处**，**不删旧条目**（`COL-R08`）。
- 理由是有实测支撑的：本专题阶段 2 靠保留「已推翻」条目救回了 **4 条错结论**。如果只在对话里，它们早被后面的话盖过去了。
- 反过来说：**写作阶段进正文的只能是最终正确版本** —— 两件事分开管，不要用一条规则覆盖两边。

### 3. 发现「Before 状态对不上」就停

对每条旧结论执行三步（`COL-C03`）：

1. 先在账本写下它的 **Before 状态**（当前状态 + 现有证据）。
2. **只录入这一次带来的那一步变化** —— 禁止把后来才知道的结论一次性回填。
3. 若发现「账本说的」和「实际翻回去看到的」不一致（例如账本写着 `一手已核`，却没人能翻回定位）→ **停下来记差异，标 `待复审`，不许静默改写**。

### 4. 旧稿特有的坑

| 坑 | 处置 |
| --- | --- |
| 旧稿里的数字已经过期 | 别改数字，改 `状态`：标 `待复审` + 写 `失效条件` |
| 旧稿引用的外部链接已死 | 记进缺口清单（「链接已死，需另找一手」），**不要把死链当定位交出去** |
| 旧稿是自己写的，所以「我记得」 | **记忆不是来源**。`状态` 只描述「核对过来源」，不描述「我记得是这样」（`COL-R02`） |
| 旧稿有多个版本 | `定位` 必须写**哪一版**；只写「旧稿」等于没定位 |

## 二、读数据（实验 / 测量 / 跑分）

### 1. 可复现要素 —— 缺一样就算不到位

「别人能不能复现这次测量」是这一类唯一的验收线（`COL-R19`）。要凑齐：

| # | 要素 | 例 |
| --- | --- | --- |
| 1 | **软件与版本** | `5.7` |
| 2 | **硬件／环境** | `RTX4090 / 32G` |
| 3 | **场景／输入** | `场景X（资产A）` |
| 4 | **基线 → 结果** | `120 → 148 fps` |
| 5 | **统计方式** | `stat unit ×3 取中位` |
| 6 | **原始数据文件** | `chart.csv`（要能指到路径） |

| 差 | 好 |
| --- | --- |
| 「性能提升明显」 | `5.7｜RTX4090/32G｜场景X（资产A）｜基线120→148fps｜stat unit ×3 取中位｜原始数据 chart.csv` |

### 2. 数据的条目怎么写

- **`状态` 用 `自测`**：自己跑出来／量出来的。**`自测` 可写进正文，但必须带测量条件**（接口 §9）。
- **测量条件不是附注，是条目正文的一部分**。缺条件 → 降级成 `二手线索`，或干脆不收。
- **单位必须写死**。数字后面没有单位，等于没有这个数字。
- `失效条件` 在这一类特别好用：`换了显卡驱动后本条作废`／`0.8.1 发布后本条作废`。**写事件，不写时间**。
- `检查方式` 写成人能跑的：`跑 bench.mjs --scene X`。这是三查里「机械可查」那一档的输入。

### 3. 数据特有的红线

1. **不许把推算值写成测量值。** 推出来的要另立一条，并在断言里写明是推算。
2. **不许只留结论、丢掉原始数据。** 原始文件找不到 → 记缺口（「结论在、数据不在」= 不可复现）。
3. **量级与精确值分开**：正文可以自由写「明显更快」，**精确值一律走 `引用路径`**（`COL-R14`）。
4. **多次测量要留散布**：跑 3 次只记中位数、不记波动范围，别人无法判断稳定性 → 至少记下 `×3 取中位`，有原始文件时保留全部数据。
5. **跑不动就记失败**：缺依赖、环境不匹配 → 进缺口清单，**不许把「应该能跑」写成结论**（`COL-C07`）。

## 三、两类材料共同的收尾

1. 有没有哪条断言的出处其实是「我记得」？（`COL-R02`）
2. 旧稿里被推翻的结论，有没有新建 `已推翻` 条目并写明理由？（`COL-R08`）
3. 数据的六个可复现要素，缺哪几个？缺的进缺口清单了吗？
4. 有没有整段搬运？（`COL-R05`）

## 四、⛔ 为什么「原理」要有专门一条路（v0.5 新增 —— **实测撞出来的**）

**现象**：一轮技术文档的成品**读起来像说明书** —— 全是"有这个按钮、参数是这些"。
**根因不在写作，在上游**：`wiki-collect` 的三个采集器（`采集-代码.md` / `采集-剧本与设定.md` / `采集-旧稿与数据.md`）**只覆盖"材料里读得到的东西"**，而**原理读不到**。

| | README / 操作稿 | **技术文档** |
| --- | --- | --- |
| 回答什么 | 这是什么、怎么用 | **为什么这样、怎么做到的** |
| 材料从哪来 | 代码 + 配置 | **代码 + 外部原理 + 作者的设计意图** |
| 现有采集器覆盖吗 | ✅ | ⛔ **不覆盖** |

**→ 原理分两半，走两条路，**同一个出口（账本）**：**

| 原理的类型 | 从哪来 | 谁采 |
| --- | --- | --- |
| **外部世界的原理**（`Paper2D` 的 sprite 结构、图集算法、官方导入管线） | **`zhihu` 检索** | **本技能按「资料」采** |
| **这个工具/故事为什么这么设计** | **作者** | **`问作者.md`** |

**⛔ 关键纪律：`zhihu` 的产出必须先落成文件** —— **只在对话里的检索结果，下一个会话看不到。**
（和 §「口述必须落成文件」是同一条道理。）

**`_src/原理-<主题>.md` 的最小形态**（不多不少，这三样缺一不可）：

```markdown
# 原理 · <主题>

> 外部资料落档。**照录，不转述**（同 `COL-R30`）。来源类型：官方文档 / 从业者文章 / 论坛贴。

## <这条原理一句话>

**原文摘录**：
> <关键片段，照录>

**出处**：<URL>　｜　**来源类型**：<官方文档 / SE / 二手线索>　｜　**拿到**：YYYY-MM-DD

**它解掉什么**：<这个工具里的哪一处、正文里的哪一句，靠它才讲得出"为什么">
```

**采进账本时**：`状态` 按来源定（官方文档 = `一手已核`；别人的文章 = `二手线索`）；
`定位` 写 `_src/原理-<主题>.md:<行>`；**有 URL 的一律同时写 URL**；
`复审周期` **必填**（外部资料是**活源** —— 页面会改、版本会升）。
- **要跑机械检查**，或要写技术专题自己的检查脚本 → `tools/check.mjs`
- ⛔ **站点自身的导航页／规范页**（分区目录、编号规则、格式说明）→ **不属任何采集类型**：按**资料**处理，**登记为源表**即可，**不要当成剧情或设定去采**（v0.5 补 —— 实测一轮的 6 份材料里有 2 份是这类：`index.md` 目录页 + `format-guide.md` 编号规范，四个入口都不覆盖它）（零依赖 node，自带自检）

### 11.1 ⛔ 加载预算（v0.4 新增 —— 实测撞出来的）

**单次运行读技能文件不超过 ~50 KB。** 超了就说明**路由不准** —— 那是**要报的问题**，不是要硬读（`COL-C24`）。

**三条具体的省法：**

- **`规则契约.md` 是索引** —— **按 ID 查**，不要通读。
- ⛔ **`tools/` 下的东西一律「跑，不读」** —— **不只是 `check.mjs`**。跑一次看输出，比读源码便宜两个数量级。（⚠️ **不写死字节数**：`check.mjs` 从 v0.4 起涨了三倍，写死的数字**第二天就过期** —— 和 `完成判据.md` §3.7 那次是同一个教训。）
- ⛔ **交付门需要的名字必须写在 `SKILL.md` 里**，不能只写在 `完成判据.md`（见 §12.1）—— 否则守预算的人**读不到它，却要拿它当门禁**。

#### ⛔ v0.5 补记：**「必读集」这个词以前没有定义**

实测一轮的**必读集本身就超预算**：`SKILL.md` 13,679 + `采集-代码.md` 6,102 + `素材账本字段.md` 13,138 + `完成判据.md` 19,391 = **52,310 B > 51,200 B**。

作者的处置是砍掉最大的 `完成判据.md`，**代价是交完都不知道「三查」是哪三查** —— 而 §12 正拿它当交付门。

→ **修法不是抬预算**（抬到 55 KB 只是把问题往后推），而是**把交付门需要的两个名字搬进 §12.1**，让 `完成判据.md` 真正变成「按需读」。
→ ⭐ **教训：路由说「该读」、预算说「装不下」，两边都没错 —— 错在没人核对过它们加起来是多少。** 以后**改路由或加文件时，顺手加一遍必读集。**

⚠️ **实测**：一轮真实使用读了 **7 个文件 / 100,367 B（本技能包的 85.7%）**，而本节写的是「按需加载、不遍历无关引用」。**那条规则当时是装饰。** 现在有了数字，它才是规则。

#### ⛔ v0.5：**虚构类的余量是零** —— 别指望还能多读一份

实测两类的**必读三件**：

| 类 | 必读 | 合计 | 占预算 |
| --- | --- | ---: | ---: |
| **技术专题** | `SKILL.md` + `采集-代码.md` + `素材账本字段.md` | 42,208 B | **82%** |
| **虚构类** | `SKILL.md` + `采集-剧本与设定.md` + `素材账本字段.md` | **50,267 B** | **98%** |

⛔ **表里的字节数是 v0.5 量的一次快照，已经涨过了** —— **改路由或加文件之后必须重量**（本节开头那句「顺手加一遍必读集」就是为此写的）：

```powershell
# 必读集现在多重？把该类的三件加起来（别抄上表的数字）
$k='C:\Users\liuyu\.dsh\skills\wiki-collect'
'采集-代码.md','采集-剧本与设定.md','素材账本字段.md','SKILL.md' | ForEach-Object {
  $p = if ($_ -eq 'SKILL.md') { "$k\SKILL.md" } else { "$k\references\$_" }
  '{0,8:N0} B  {1}' -f (Get-Item $p).Length, $_
}
```

⛔⛔ **「按需」的文件不进必读集 —— 但它们必须有加载信号，否则作者会漏读**（v0.5 再补 —— 又一轮实测撞出来的）：
- **`问作者.md`（9,559 B）→ 按需**：只在「缺口清单里有只有作者才知道的项」时读。
  ⛔ **它一度既不在必读集、又不在 §11 的信号表里** —— 而那个专题的任务明令要用它，
  **结果是作者自己发现、自己加进必读集，把技术专题的必读集顶到 56,706 B（超预算）。**
  → ⭐ **教训：加文件时「进不进必读集」和「有没有加载信号」是两件事，两件都要做。**
- **`完成判据.md` / `冲突裁决.md` / `子代理.md` / `规则契约.md` → 按需**（§11 各有信号）。

⛔ **所以虚构类的余量只有 933 B。任何额外读取都是要报的问题。**
⛔ **而这正是 v0.5 要修 `素材账本字段.md` 的原因**：实测一轮的作者为了搞清 `钉死` 的取值语法，**被迫去读了 `check.mjs` 的源码三段**（违反本节「工具只跑不读」）—— 因为那个语法**只写在 `规则契约.md` 与 `check.mjs` 里，没写在字段文档里**。
→ **字段的取值语法必须写在 `素材账本字段.md`**，否则守预算的人只能去读检查器。
