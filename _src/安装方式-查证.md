## 1. 默认加载根（按 rank 顺序扫描，**五个**）

| Rank | 来源 | 路径 |
| --- | --- | --- |
| 100 | `project-dsh` | `<项目根>/.dsh/skills` |
| 200 | `project-agents` | `<项目根>/.agents/skills` |
| 300 | `custom` | 配置项 `customSkillDirs` |
| **400** | **`user-dsh`** | **`<dshHome>/skills`** —— `dshHome` 默认 `$DSH_HOME` 或 **`~/.dsh`** |
| 500 | `user-agents` | `<agentsHome>/skills` —— 默认 `$DSH_AGENTS_HOME` 或 `~/.agents` |

**⭐ 两条推论**（对安装说明很关键）：

- **装一次给所有项目用** → 放进 **`~/.dsh/skills/`**（rank 400）
- **只给某一个项目用** → 放进 **`<项目根>/.dsh/skills/`**（rank 100，**优先级最高**）
- ⚠️ **`<项目根>` = 「含 `.git` 的最近祖先目录」**；不存在则用当前工作目录

## 2. 技能形态（两条都合法）

- **目录 bundle**：`<技能名>/SKILL.md` ← **我们这三个都是这种**
- **平铺文件**：`<技能名>.md`

⛔ **刻意不支持嵌套的 `**/SKILL.md`** —— 所以**不能**把技能塞进一个子目录里（例如
`~/.dsh/skills/my-skills/wiki-collect/SKILL.md` **不会被发现**）。

## 3. frontmatter 里真正会被读到的字段

| 字段 | 读不读 | 说明 |
| --- | --- | --- |
| `name` | ✅ **必填** | 必须匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$`；**不合规则整条技能被忽略**（日志只有一行 `ignored: invalid skill name`） |
| `description` | ✅ **必填** | 缺失则整条技能不加载 |
| `whenToUse` | ✅ 选填 | 独立字段，写触发场景 |
| `disable-model-invocation` | ✅ 选填 | `true` = 把该技能**从面向模型的目录与 loader 中排除** |
| `user-invocable` | ✅ 选填 | `false` = 从面向用户的命令中排除 |
| `metadata` | ✅ 选填 | 对象 |
| **其它一切**（`license:` / `version:` / `tags:`…） | ❌ **静默忽略** | **不报错，也读不到** —— **许可信息必须写在正文里** |

## 4. 生效时机

**监视是默认开的**（配置项 `watch`，默认 `true`）：**新增、改名、删除技能会被自动发现** ——
**不需要重启 DSH**（这一点与插件不同）。

## 5. 与「技能编写」有关的其它事实

- 扫描时会**跳过 `<dshHome>/.system` 子目录**
- `includeDefaultRoots: false` 会省略项目根、用户根与 `$DSH_BUNDLED_...`
- 挂载要两个包一起上：`@deepseek-ai/dsh-skill` + `@deepseek-ai/dsh-skill-filesystem`
